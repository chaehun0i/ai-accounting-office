# 회사 초기 설정과 계정과목 확장

## 처음 설정과 이후 관리

회사별 서버 온보딩 상태가 COMPLETED가 아니면 업무 홈에 다섯 단계의 직접입력 화면을 표시한다.

1. 회사정보: 사업자 유형에 맞는 회사 기본정보를 확인한다.
2. 회계 기준: 기능통화, 회계연도 시작 월, 회계기준과 전표번호 기준을 확인한다.
3. 거래처: 필요한 거래처를 입력한다. 거래처가 없으면 생략할 수 있다.
4. 기초잔액: 기존 장부 잔액을 입력하거나 기초잔액 없음을 명시적으로 확인한다.
5. 최종 확인: 요약과 서버 검증 결과를 확인한 뒤 권한 있는 사용자가 완료한다.

‘저장하고 다음’은 저장 성공 후에만 이동한다. 필수 항목은 서버 Field Catalog의 규칙을 사용하며 법인등록번호는 법인일 때 요구한다. 자동 계산값은 반복 입력 행이나 필수 입력 분모로 세지 않는다. 빈 새 항목의 팝업을 취소하면 빈 행을 남기지 않고, 이미 입력한 내용은 저장하거나 명시적으로 이동을 확인할 때까지 유지한다.

서버에 저장한 값이 정본이다. localStorage에는 회사 UUID별 마지막 단계 코드만 저장한다. 개인정보·입력값·완료 여부를 저장하지 않는다. 단계 힌트가 잘못되거나 저장소를 쓸 수 없으면 첫 단계부터 안내한다. 회사 전환은 별도 컴포넌트 상태로 분리하고 서버 권한을 계속 검증한다.

완료한 회사의 홈은 실제 전표 현황과 다음 업무를 보여준다. `/onboarding` 직접 진입도 초기 설정을 다시 편집하게 하지 않는다. 이후 `/accounting`의 **설정 관리**에서 회사정보 / 회계 기준 / 계정과목을 구분한다. 회사정보는 기존 API가 허용하는 회사명·주소만 expected_version과 함께 수정한다. 회계 기준도 기존 정책 API의 허용 범위를 유지한다. 권한이 없으면 조회 안내를 제공하며 서버 검사를 우회하지 않는다.

완료 여부는 입력률이나 브라우저 단계 위치로 판단하지 않는다. 최종 서버 검증과 원자적 완료 명령을 사용한다. 아직 지원하지 않는 데이터는 보존하고 서버가 완료를 차단한다. 기초잔액은 ‘없음’ 선택만으로 삭제되지 않으며, 잔액 UPDATE나 자동 Posting을 만들지 않는다. 기초 전표 작성·별도 사용자 승인·장부 반영은 기존 회계 명령을 사용한다.

## 서버 고정 계정목록

`KR_STANDARD` 버전 1의 25개 계정과 템플릿 UUID·계정 의미는 그대로 유지한다. 버전 2는 130개 계정이다. 현금·금융자산·채권·재고·유무형자산·차입금·자본·수익·매출원가·제조원가·일반 경비를 포함한다. 계정코드는 이 프로젝트의 명시적인 버전 계약이며 더존의 코드를 복제한 것이 아니다. 모든 업종의 완전한 법정 계정체계라는 의미도 아니다.

버전별 생성과 검증은 공통 `_accounts`와 `_seed_version`, 회사별 준비는 기존 `prepare_accounts`를 재사용한다. 회사 생성·기존 회사 보충·회계 기준 초기화가 같은 준비 계약을 사용한다. 재실행 시 누락 계정만 추가한다. 기존 회사의 계정 ID·이름·템플릿 참조·생성 시각·기존 전표 참조를 변경하지 않는다. 기존 초기화 요청도 v1/v2의 알려진 참조를 인식한다. 임의 템플릿 선택은 계속 차단한다.

분류 계정과 전표 입력 가능 계정을 구분한다. 차감 계정의 정상 잔액 방향을 검증한다. 설정 화면은 조회 전용이며 코드·이름 검색과 자산/부채/자본/수익/비용 필터를 제공한다. 계정 추가는 Asset/Inventory/Tax 업무 기능의 선행 구현이 아니다. 새 migration이나 업무 컬럼을 추가하지 않았다. 현재 head는 `008_governance`다.

## 검증

- Python 단위/계약: 157 passed. PostgreSQL 전체 통합: 105 passed. 기존 Starlette/httpx deprecation warning 1건은 남아 있다.
- PostgreSQL 검증에는 빈 DB migration, downgrade/upgrade, metadata diff, 회사 격리, 계정 보충의 재실행·기존 ID/참조 보존, 기존 Onboarding 및 공식 2025 Golden 회귀가 포함된다. 격리 DB는 실행 후 삭제한다.
- Ruff check/format, mypy(249 모듈), pip check 통과.
- 프론트엔드: 21 tests, lint/typecheck 및 Compose production build 검증.
- 실제 로컬 DB: 업무 테이블 53개, JSON 0, JSONB 0, FK 118개, orphan 0. 계정 seed는 schema 변경이 아니다.
- 브라우저 검증은 `scripts/navigation-browser-smoke.cjs`를 사용한다. 실제 로그인·단계 이동·새로고침 복구·팝업·미저장 이동 취소·설정 탭·계정 검색·모바일·권한 안내를 검증한다. 완료 상태의 홈/초기 설정 재진입 분기는 GET 응답만 COMPLETED로 모의하여 확인한다. 실제 기존 회사 초안은 완료하거나 수정하지 않는다. 서버 완료·롤백·권한 계약은 PostgreSQL 통합 테스트가 검증한다.

## 남은 범위

설정 화면은 기존 서버가 허용하는 필드만 수정한다. 사업자 식별자 변경, 이미 생성된 회계연도의 시작 월 변경, 미지원 Domain 승격을 임의로 열지 않는다. 공식 2025 fixture와 기대 금액은 변경하지 않았다. 현재 기본 템플릿의 valid_from은 기존과 같은 2026-01-01이며 과거 장부 준비는 별도 계약이다.
