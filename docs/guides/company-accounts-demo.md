# 회사별 계정과목과 연간 체험 자료

## 계정과목

참고 파일 `계정과목 리스트 (1).xlsx`의 5개 시트, 123개 명칭을 기존 기본 목록과 대조했다. 기존 v2의 130개 계정을 보존하고 필요한 상세 계정을 추가한 `KR_STANDARD` v3는 175개다. 이 중 170개는 분개 가능하고 5개는 분류 계정이다. 가산·차감 같은 집계 제목은 분개 계정으로 만들지 않았으며 기존 동의어 계정을 중복 생성하지 않았다. 원본 파일과 이전 템플릿은 수정하지 않았다.

기존 회사에는 누락된 기본 계정만 추가한다. 기존 계정 ID와 전표 참조를 유지하며 회사가 추가한 계정도 초기화 재실행 시 보존한다. 사용자 화면은 **설정 관리 → 계정과목 → 우리 회사 계정과목 추가**다.

`POST /accounts`는 `account.create` 권한과 현재 회사 인증을 요구한다. 회사 ID는 요청 본문으로 받지 않는다. 회사별 코드 중복을 차단하고 상위 계정도 같은 회사에서 조회한다. 다른 회사에서는 해당 사용자 계정을 조회하거나 상위 계정으로 참조할 수 없다. 차감 계정 여부와 계정 유형으로 정상 잔액 방향을 결정하며 저장은 Application Unit of Work가 소유한다. 새 migration은 필요하지 않다.

기본 외상매출금·받을어음·장기매출채권 및 외상매입금·지급어음·미지급금·장기성매입채무는 기존 채권·채무 인식과 원장 대사 정책에 연결했다. 임의 사용자 계정명을 채권·채무 통제계정으로 자동 추측하지 않는다. 사용자 계정별 통제계정 역할 설정은 후속 범위다.

## 로그인과 체험 범위

- 회계담당자: `annual-demo@example.com`
- 별도 승인담당자: `annual-reviewer@example.com`
- 무작위 비밀번호: Git에서 제외된 `.local/annual-demo-accounts.ini`
- 회사: `가온푸드웍스 · 2025 연간 체험회사`
- 조회 기간: **2025-01-01 ~ 2025-12-31**

작성자와 승인자는 서로 다르다. 실제 사용자에게 필요한 승인 경계를 없애지 않았다. `scripts/bootstrap_annual_demo.py --approve-synthetic-fixture`는 로컬 합성 자료 준비 전용이며 명시적으로 승인된 테스트 자료를 기존 인증 API로 제출·승인·확정한다. 운영 환경 및 실제 은행 지급에는 사용하지 않는다. 로그인 비밀번호를 저장소나 로그에 기록하지 않는다.

공식 native Google Sheet의 기존 `native-2025-v1` CSV 스냅샷을 읽으며 원본을 수정하지 않는다. `.xlsm`은 공식 입력 fixture가 아니다. 매출 240건, 매입 74건과 대응 수금·지급을 처리했다. 급여·자산·재고·세무 전체 연간 업무까지 구현됐다는 의미는 아니다. 기초잔액은 이 체험회사에서 명시적으로 없음 처리했다.

## DB와 로컬 실행

PostgreSQL 컨테이너는 하나이며 업무 DB는 `accounting_office` 하나다. `postgres`는 서버 기본 관리 DB다. 이번 검증용 임시 DB는 종료 후 삭제했다. 업무 `public` schema의 JSON/JSONB 컬럼은 0개다.

기존 로컬 DB에는 별도 진행 중 PR의 `010_agent_runtime_foundation`이 이미 적용돼 있었다. 이를 내리거나 미병합 PR을 이 브랜치에 합치지 않았다. 이번 브랜치는 main 기반이며 신규 migration은 없다. 현재 backend 컨테이너에는 변경된 계정과목 관련 파일만 반영해 기존 Agent 실행 코드와 migration을 보존했다. frontend는 새 이미지로 빌드했다. 현재 배포를 재생성할 때에는 기존 Agent 코드가 포함된 통합 브랜치를 사용해야 한다. 이 브랜치 단독 backend 재빌드는 현재 010 DB와 맞지 않으므로 수행하지 않았다.
