# 서버 계정목록과 회계 작업 공간

계정과목을 사용자가 골라 생성하는 초기 설정에서 서버 제공 목록을 사용하는 흐름으로 변경했다. 최초 관리 목록은 `KR_STANDARD` 버전 1의 25개 계정이었다. 현재 버전 2는 130개이며 기존 계정 참조를 보존한다. [단계형 초기 설정과 계정 확장](first-company-setup-and-account-catalog.md)을 참고한다. 이 목록을 모든 업종의 완전한 법정 계정체계라고 주장하지 않는다. 추가 계정이 필요하면 검토한 새 카탈로그 버전으로 배포한다.

## 계정과목 준비

- 신규 회사 생성은 회사·소유자 멤버십·기본 계정을 동일 UoW 안에서 준비한다. 계정 준비 실패 시 전부 롤백한다.
- 로컬 Compose의 기존 템플릿 seed 실행은 회사 행을 잠그고 누락된 기본 계정을 보충한다. 재실행 시 기존 계정 ID, 이름, 전표 참조를 수정하거나 삭제하지 않는다.
- 계정 생성의 공통 함수는 `accounting/application/catalog.py`의 `prepare_accounts`다. 회사 생성, 기존 회사 보충, 회계연도 초기화가 이 함수를 사용한다.
- 회사별 UUID와 회사 범위 FK는 유지한다. 공용 계정 ID를 모든 회사가 함께 사용하는 방식으로 바꾸지 않는다.
- `/accounting/initialize`에서 템플릿 ID 생략 시 서버 기본값을 사용한다. 기존 클라이언트의 기본 ID는 허용하지만 다른 템플릿은 권한 검증 후 거부한다.
- 계정목록은 회계연도 설정 전에도 조회한다. 기간 생성과 전표번호 정책은 여전히 관리자 설정이며 임의의 회계연도를 자동 생성하지 않는다.
- 온보딩의 계정과목은 조회·검색 전용이다. 서버 계정을 온보딩 기본값으로 제공하고 입력 진행률 분모에 넣지 않는다. 준비된 계정의 이름 변경이나 새로운 계정 승격은 서버에서 차단한다.

기존 온보딩/Golden fixture의 이전 코드 체계는 조용히 수정하지 않았다. 이미 저장된 사용자 계정과 초안도 삭제하지 않는다. 운영 회사에는 기본 계정이 보충되므로 이전 Excel 계정과 서버 목록이 다르면 자동 덮어쓰기하지 않고 정합성 확인이 필요하다. 이전 계약의 빈 계정 회사 fixture는 호환 검증을 위해 유지한다.

## ESG 화면에서 반영한 구조

참고 저장소는 `shell-files/dev_skm`, commit `720e33c7923a679c2cff694ca12c9f92646ed06b`다.

| 실제 파일 | 분류 | 반영 내용 |
| --- | --- | --- |
| `frontend/src/homes/onboards/OnBoard.jsx` | ADAPT | 상단 통계, 항목 탐색, 입력·검증·완료 작업 공간 |
| `frontend/src/homes/onboards/OnboardingMetricTable.jsx` | ADAPT | 반복 입력의 목록·상태·입력 팝업 |
| `frontend/src/homes/Dashboard.jsx` | PATTERN | 선택한 작업 범위, 업무 단계 안내, 현황과 최근 기록 |
| `frontend/src/homes/mains/Manager.jsx` | PATTERN | 목록에서 상세 편집으로 진입하는 패턴 |

프로젝트 개념은 회사와 실제 회계기간으로 치환했다. 별도의 가짜 프로젝트 정본을 만들지 않았다. 원본의 mock 프로젝트·진행률·공지, ESG 지표, Redux/React Router 의존성은 가져오지 않았다. 팝업과 동작 효과는 앞서 도입한 Radix Dialog·Framer Motion 공통 계층을 유지한다.

## 회계 홈

회계기간 선택, 초안·검토 대기·반영 대기·반영 완료 건수, 최근 전표와 상세 링크를 제공한다. 모두 해당 회사의 실제 API 응답이다. 조회 전·권한 없음·실패 상태를 0건으로 위장하지 않는다. 현재 전표 조회 API의 최대 500건 제한을 화면에 표시하므로 전체 기간의 대량 집계를 의미하지 않는다.

## 온보딩

회사 기본정보는 직접 입력이 기본이다. Excel 업로드 버튼은 상단 한 개를 유지한다. 거래처·기초잔액 같은 반복 항목은 목록과 입력 팝업으로 구성한다. 팝업의 저장은 기존 optimistic version 계약을 사용한다. 닫기만으로 저장되지 않으며 페이지를 떠나면 저장하지 않은 입력은 사라진다.

진행률은 서버가 반환한 입력 대상의 complete/total을 집계한다. 고정 계정목록은 제외한다. 이 수치는 승인·Posting 완료율이 아니다. 절차 안내 역시 회계 승인 상태를 자동 변경하지 않는다.

## 검증 범위

고정 계정 자동 준비, 재실행 시 ID 보존, 회사 격리, 기본 템플릿 선택, 온보딩 계정명 변경 거부, 회사 생성 롤백을 PostgreSQL에서 검증한다. 기존 회계 마스터·온보딩·Golden 회귀도 실행한다. 테스트용 DB는 실행 후 제거하고 개발 DB를 초기화하지 않는다.

프런트엔드는 진행률 단위 테스트와 전체 기존 테스트, lint/typecheck/build, 실제 브라우저의 홈·고정 계정 검색·입력 팝업·Excel 팝업·모바일·권한 안내를 검증한다. 상세 실행 결과는 PR 본문에 기록한다.

### 실제 실행 결과

- Backend 단위·계약: 156 passed, 기존 Starlette deprecation warning 1건.
- PostgreSQL 회계 마스터·온보딩·Golden 회귀: 39 passed, 기존 warning 1건. 최종 고정 계정 준비·변경 차단·회사 생성 롤백: 별도 재실행 3 passed.
- Ruff check/format, mypy(249개 소스), pip check 통과.
- Frontend 전체 16 tests, lint, typecheck 통과. Windows와 Compose의 production build 통과.
- 실제 브라우저: 9개 경로, 회계기간과 실제 전표 건수, 계정 검색·추가 버튼 없음, 온보딩 입력 팝업, Excel 팝업, 포커스·Escape·배경 클릭 보호, 새로고침, 권한 안내, 모바일 배치, 움직임 줄이기 통과.
- 실제 브라우저 회계 흐름: 거래 작성 → 전표 제출 → 별도 사용자 승인 → 장부 반영 → 원장·시산표 통과.
- 개발 DB 조회: 업무 테이블 53개, JSON 0개, JSONB 0개, FK 118개, orphan 0건, head `008_governance`. 스키마 변경 없음.
- Compose의 PostgreSQL·Redis·Backend·Frontend healthy. 검증용 DB는 종료 후 제거.

초기 검증에서 권한보다 템플릿 검증을 먼저 수행해 5개 RBAC 테스트가 실패한 문제를 발견했다. 회사 권한을 먼저 확인하도록 수정하고 39개 통합 회귀를 다시 통과했다. Windows 샌드박스 파일 생성 권한으로 빌드가 중단된 건은 권한 적용 재실행에서 통과했다. 브라우저 검증의 이동 직후 새로고침 경합은 URL 이동을 기다리도록 보정했다. 회계 흐름 스크립트의 이전 기본 포트는 현재 Compose 주소를 명시해 재실행했다.


## 사용자 흐름 개선

입력한 칸의 비율을 온보딩 전체 완료율처럼 표시하던 요약을 제거했다. 입력 대상이 0개인 영역을 미입력으로 집계하지 않고 ‘내용 확인’으로 안내한다. 완료 가능 여부는 계속 서버의 `READY_TO_COMPLETE` 상태를 따른다.

- 업무 홈: 선택 기간의 전표 상태와 권한에 맞춰 검토, 장부 반영, 전표 작성 또는 원장 조회를 안내한다. 조회 실패를 무한 로딩처럼 표시하지 않는다.
- 회계 준비: 저장 필요 → 입력 내용 확인 → 회계 준비 완료 순서로 안내한다. 완료 버튼이 비활성화된 이유와 관리자 권한이 필요한 경우를 설명한다.
- 미저장 보호: 메뉴·링크를 통한 다른 업무 페이지 이동, 회사 선택, 로그아웃 전에 동일한 확인 경계를 사용한다. 새로고침·브라우저 종료는 브라우저 기본 경고를 사용한다. 확인을 취소하면 입력을 유지한다. 자동 저장 기능은 아니다.
- 검증 오류: ‘해당 항목 확인’으로 해당 영역 또는 목록 입력 팝업을 연다.
- 표시 정리: 반복되는 기본값·초안 표시를 줄이고, 기초 전표 생성 후 내부 식별자 대신 전표로 이동하는 링크를 제공한다.
- 계정 검색: 검색 결과가 없을 때 다음 검색을 안내한다. 고정 계정목록은 조회 전용이다.

검증: 프론트엔드 테스트 17건, lint, typecheck, 로컬 production build 및 Compose production build 통과. 실제 Edge에서 9개 경로, 팝업, 모바일 배치, 미저장 상태의 이동·로그아웃 취소, 이동 후 저장값 복구를 확인했다. 기존 테스트 계정을 사용했으며 브라우저 검증에서 회사정보를 저장하거나 새 업무 데이터를 생성하지 않았다.

제한: 다음 할 일은 선택 기간에 조회된 전표 최대 500건을 기준으로 한다. 업무 홈의 링크는 해당 업무 목록으로 이동하며 기간 필터를 자동 전달하지 않는다. 입력 팝업에서 저장하면 현재 페이지의 변경 내용을 함께 저장한다. 브라우저의 뒤로·앞으로 이동을 가로채는 별도 기능은 아직 없다.


기존 PR의 PostgreSQL CI에서 발견한 Golden 충돌도 수정했다. 사용자용 초기화는 고정 기본 양식만 허용하므로 테스트에서 임의 템플릿을 선택하던 준비 과정이 실패했다. 공식 2025 파일과 기대 금액은 유지하고, 테스트 DB에서 2025년 기존 회계기간·계정체계를 명시적으로 준비한 뒤 기초전표 → 승인 → 확정 → 원장 → 시산표를 검증한다. 현재 기본 양식의 유효 시작일은 2026-01-01이며, 이 테스트를 새 회사의 2025년 기본 양식 초기화 지원으로 해석하면 안 된다.


최종 PostgreSQL 전체 통합 검증: `tests/integration --require-postgres -s` 104 passed (180.71초). 기존 Starlette TestClient/httpx 사용 중단 예고 warning 1건. clean migration 및 metadata diff 검증도 통합 테스트에 포함된다. Golden의 원장·시산표 차변/대변 280,000,000원 기대값은 변경하지 않았다. 검증용 `accounting_ui_test` DB는 종료 시 삭제했다. 수정한 Python 테스트의 Ruff check/format check 및 `git diff --check`도 통과했다.
